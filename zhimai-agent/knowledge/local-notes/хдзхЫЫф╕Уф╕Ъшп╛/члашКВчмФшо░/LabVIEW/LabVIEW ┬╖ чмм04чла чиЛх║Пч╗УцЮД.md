## 可直接使用的知识

While 循环适合条件驱动的持续任务，For 循环适合已知次数的数据处理。移位寄存器保存上一次迭代的状态，是滤波、累计和状态机的基础；未初始化移位寄存器会跨 VI 调用保留值，必须有意使用。

条件结构的每个输出隧道都应在所有分支中赋值。事件结构适合处理界面事件；若事件分支执行耗时采集，界面会被冻结，因此常用“事件生产者 + 消费者状态机”。

顺序结构能强制次序，但过度使用会遮蔽数据依赖。优先用错误线、状态机和消息队列表达顺序。局部变量和属性节点可能引入竞态，只有在无法直接连线时使用。

实用状态机由枚举状态、While 循环和移位寄存器组成。每个状态只做一件事，并明确下一状态与错误出口。

## 课堂补充

## 可复现实验：事件控制采集循环

本节为依据 NI 文档设计的学习实验，与教材第 4 章的“循环、事件结构”目录相对应；不是教材示例程序。

1. 在前面板创建“开始”“停止”两个按钮和一个数值指示器。建立两个并行 While 循环：界面循环放 Event Structure，工作循环放 Dequeue Element。循环外先用 Obtain Queue 建立队列，将队列引用传入两环。
2. “开始”的 Value Change 事件只入队 `Start` 消息；“停止”事件入队 `Stop` 后退出界面循环。工作循环用移位寄存器保存 `running` 布尔值与计数值，并给 Dequeue Element 设 100 ms 超时：收到 `Start` 置 `running=true`，超时且 `running=true` 时加 1，收到 `Stop` 退出工作循环。超时不是通信错误，应与真实错误分开处理。避免在事件分支中执行长时间采集。
3. 结束时确认两循环都能退出，再 Release Queue；错误线贯穿初始化、处理和释放。若显示更新需要跨循环通信，可改用消息或用户事件，避免多个循环同时写同一局部变量。
4. 测试：快速连续按 10 次“开始”；采集中按“停止”；工作任务故意延时 1 秒时仍能响应界面。检查队列积压是否持续增长，必要时限制生产速率或制定丢弃策略。

事件结构负责接收操作，工作循环负责耗时任务；二者的执行顺序靠队列消息定义。NI 的 QMH 模板可通过 LabVIEW 的“Create Project → Queued Message Handler”查找；具体菜单和模板以已安装版本为准。

**来源**：[NI：Producer/Consumer Architecture](https://www.ni.com/en/support/documentation/supplemental/21/producer-consumer-architecture-in-labview0.html)、[NI：Queued Message Handler](https://www.ni.com/en/support/documentation/supplemental/21/using-a-queued-message-handler-in-labview.html)、[NI：队列引用释放与超时处理](https://knowledge.ni.com/KnowledgeArticleDetails?id=kA00Z0000019LYuSAM&l=en-US)、[清华大学出版社：本书目录](https://www.tup.tsinghua.edu.cn/bookscenter/bookcatalog?id=07683001)。NI 页面说明设计模式，出版社页面仅核对本章主题。
