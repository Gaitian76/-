## 可直接使用的知识

混合编程的目标是把在 HDevelop 中验证的算法集成到稳定应用。可选择导出代码、调用 HALCON/.NET 或 C++ 接口，或通过 HDevEngine 执行过程；选择取决于维护、性能和授权部署需求。

工程架构应分离采集、算法、UI 和设备通信。采集线程提供带时间戳的图像，算法模块返回结构化结果，UI 只显示，控制模块负责握手与异常状态。

HALCON 对象和句柄有生命周期，长期循环中要及时释放不再使用的图像、区域、模型和窗口资源。避免在 UI 线程执行耗时算子，防止界面无响应。

部署测试包括运行库/许可证、相机驱动、字符编码、路径、异常日志、断线重连和连续运行内存。算法参数应配置化并带版本，不能散落在界面事件中。

## 课堂补充

### HDevelop 到 C++ 的最小接口设计

将视觉算法封装为纯过程 `Inspect(Image, Config) -> {status, score, row, column, reason}`，其中 `status` 至少区分检出、未检出、运行异常；空匹配不能直接访问 `Row[0]`。图像采集、PLC 交互和 UI 留在宿主程序，算法过程只返回结果和必要的可视化轮廓。这样可把同一组测试图与期望结果用于 HDevelop 和宿主程序的回归核对。

MVTec 官方提供两条集成路径：HALCON/C++ API 调用算子，或通过 HDevEngine 在应用中运行 HDevelop 过程；后者在官方文档中还提供过程导出生成包装代码的方式。选择时核对目标操作系统、HALCON 运行库、许可证、相机接口和线程模型。先在无相机的离线图片集上验证返回值、异常处理和重复加载/释放，再接设备。

来源：[MVTec HDevEngine 说明](https://www.mvtec.com/products/halcon/features-tools/development-tools-programming/hdevengine)、[MVTec HALCON Programmer's Guide](https://www.mvtec.com/fileadmin/Redaktion/mvtec.com/products/halcon/documentation/manuals/programmers_guide.pdf)。文档网页会随版本更新；具体 API、编译参数及部署许可，以本机安装的 HALCON 文档及授权为准。
